# java-calculator-precourse
구현사항
---
### 구현체 구현 목록
1. CalculatorTokenizer : 
   1. 추상화 :
   단어의 파싱을 담당한다, 기준에 맞게 단어들을 끊어준 컬렉션을 반환하는 책임을 가진다.
   2. 구현 :
   토크나이징 된 문자열 리스트를 반환하는 구현체를 제작한다.
2. MeaningRapper :
   1. 추상화 :
   파싱된 문자열 컬렉션을 받아들여 각 의미가 무엇인지를 표시하는 객체로 래핑하여 리턴하는 책임을 가진 클래스.
   커스텀 구분자로 판단되어야 하는 구문은 여기서 걸러지며 새로운 문자 규칙으로 추가된다.
   2. 구현 :
   리스트를 받아들이고 그 리스트의 각 문자열을 보고 규칙을 판단하여 의미를 가지는 객체로 변환 및 래핑한 리스트를 반환
3. ASTMaker :
    1. 추상화 :
       MeaningRapper에서 구현한 컬렉션을 받아들여 파싱 규칙에 맞는 연산이 가능한 컬렉션을 반환하는 클래스.
    2. 구현 :
       받아들인 리스트를 순차적으로 읽어들여 파싱 규칙에 맞게 연산할 수 있는 중위탐색 기반 트리를 반환
4. OperationalCollectionCalculator : 
   1. 추상화 :
      ASTMaker에서 반환하는 연산 컬렉션 규칙에 맞게 실제 연산을 수행하여 그 결과값을 반환하는 책임을 가진 클래스.
   2. 구현 :
   받아들인 트리를 중위 탐색하여 실제 연산을 수행하고 그 결과값을 리턴한다.
5. MeanTokenEntity :
   1. 추상화 :
   meaningRapper가 래핑하는 결과물, 이것으로 오퍼레이셔널 컬렉션 메이커가 구분 가능한 객체 요소가 탄생한다.
   2. 구현 :
   숫자 구현체(실수인지 정수인지 판단하여 해당 자료형으로 자료 보관),
   오퍼레이터 구현체(+, -) 등의 연산자 여부를 판단하고
   연산 순서 레벨과 실제 단순 연산 수행 메소드를 가져서 오퍼레이셔널컬렉션 칼큘레이터가 그 메소드를 호출해서 실제 연산 진행
5. Operators
   1. 추상화 : 오퍼레이터들을 모아놓는 컬렉션, 미닝래퍼에서 오퍼레이터로 분류된 녀석들을 이곳에 저장하고 커스텀 오퍼레이터 추가시 검증하는 요소들이다.
   2. 구현체 : PlusOperators를 기본으로 가지지만 빼기 곱하기 등의 컬렉션을 나중에 확장 가능하도록 구현체와 추상화 레이어를 나눔
#### 제약 조건
##### 전체 해석 vs 순차 해석
1. 위 계산기는 순차 해석을 기본으로 채택한다, 즉, 커스텀 구분자는 추가하는 다음 문자열 요소들에만 적용된다.
##### 
##### 구분자 제약 조건
1. 숫자
   1. 숫자는 0~9까지의 문자 데이터로 규정한다.
   2. 실수 표현을 위한 .또한 제약 조건에 포함시킨다.
2. 연산자
   1. 기본적으로 더하기만 사용하나, 다른 연산 기호 확장을 고려한 설계를 반영한다.
3. 커스텀 구분자
   1. 구분자 컬렉션을 사전 생성하여 커스텀 구분자를 거기에 추가하는 방식으로 구현한다. 사전 추가 구분자는 ,와 :로 구성되는것과 후술할 이유로 . 도 추가시킨다.
   2. 커스텀 구분자는 //$구분자\n 인 점을 고려하여, //나 \n는 구분자로 등록할 수 없게 한다.(이것들이 등록 가능하게 되어버리는 순간 커스텀 등록자와 연산기호 간의 이중 역할이 생겨 구분이 불가능하다.)
   3. 양수 표현 중 실수 표현에 사용이 가능한 .은 사전 구분자로 추가한다.
   4. //가 시작되는 순간 그 뒤의 문자들을 전부 받아들이기 시작하는데 \n으로 끝내지 않고 모든 로직이 끝나면 예외를 반환하게 한다.
