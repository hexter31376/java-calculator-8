# java-calculator-precourse
구현사항
---
### 구현체
#### config
AppConfig : 어플리케이션 요소들의 생명 주기를 관리하는 config, 생성은 이곳에서만 진행하여 IOC를 보장한다.
#### view
Inputview : 문제 조건에 맞는 템플릿 문장 출력 및 입력을 받는 뷰
Outputview : 문제 조건에 맞는 템플릿 문장 출력 및 결과의 출력을 하는 뷰
#### presentation
CalculatorController : CalculatorService를 호출하여 메인 로직을 수행하고 인풋뷰와 아웃풋뷰의 입출력을 조절하는 컨트롤러
#### application
CalculatorService : ParsorService를 호출하여 파싱을 진행하고 파싱한 데이터로 연산을 수행하는 서비스, 숫자를 리턴한다.

#### parsor
ParsorService : 실제 데이터의 파싱을 진행하고 연산 가능한 컬렉션을 돌려준다.

#### delimiter
Delimiter : 구분자 자체를 저장하고 내보내며 저장하기 전 유효성 검사를 실시한다
Delimiters : 구분자 자체를 리스트로 저장하며 리스트 항목들이 전부 포함된 정규식 포맷을 만들어낸다.

##### 제약 조건
1. 숫자
   1. 숫자는 0~9까지의 문자 데이터로 규정한다.
   2. 실수 표현을 위한 .또한 제약 조건에 포함시킨다.
2. 연산자
   1. 기본적으로 더하기만 사용하나, 다른 연산 기호 확장을 고려한 설계를 반영한다.
3. 커스텀 구분자
   1. 구분자 컬렉션을 사전 생성하여 커스텀 구분자를 거기에 추가하는 방식으로 구현한다. 사전 추가 구분자는 ,와 :로 구성되는것과 후술할 이유로 . 도 추가시킨다.
   2. 커스텀 구분자는 //$구분자\n 인 점을 고려하여, //는 구분자로 등록할 수 없게 한다.(이것들이 등록 가능하게 되어버리는 순간 커스텀 등록자와 연산기호 간의 이중 역할이 생겨 구분이 불가능하다.)
   3. 양수 표현 중 실수 표현에 사용이 가능한 .은 사전 구분자로 추가한다.
   4. //가 시작되는 순간 그 뒤의 문자들을 전부 받아들이기 시작하는데 \n으로 끝내지 않고 모든 로직이 끝나면 예외를 반환하게 한다.
   5. 커스텀 구분자 내에서는 공백을 허용하지 않는다. // ;    ;\n과 같은 구분 단위를 파악하기 어렵게하고, 문자열 파싱 로직을 혼란스럽게 하는 문법이기 때문이다.
   6. 커스텀 구분자 내에서는 숫자를 허용하지 않는다. 변수 선언시에는 유용한 옵션이지만, 입력값에 구분자로 숫자가 섞여있으면 구분자와 숫자를 연속으로 섞었을 때 파악이 어려워지고, 내부 서비스 로직의 시간복잡도를 쓸데없이 증가시킨다.
